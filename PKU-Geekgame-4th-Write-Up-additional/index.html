异或和打乱顺序都是可逆的，考察Datalab
要求average_bit_count(prefix) < 2.5和特定字符
gzip 的编码方式LZ77 压缩把重复出现的字节+Huffman 编码产生最终结果
而LZ77 仅在输入包含三个字节以上的重复子串时才起作用
所以可以通过构造避免LZ77 的出现
剩下 Huffman 树，它可以是预先定义的 Fixed huffman code（blocktype == 1），也可以是随数据变化的 Dynamic huffman code（blocktype == 2）
但ASCII码也就6-7bits，Fixed Huffman Code 需要8bits，可以假定是Dynamic的
同时gzip的Huffman具体表示方法仅记录了树上每个字符的长度,如Fixed Huffman code如下

256为EOF
可以直接构造000000-111110这 63 个字符，避免三个字节以上的重复子串，EOF，较短的输入以避免其他的Huffman树编码
Flag1 就是在前256构造popcount为0，1，2的字符（使得$popcount_{average}6/8<2.5$）,为0有1个，为1有6个，为2有15个共22个，重复15遍，$15226/8$ 差不多256，平均 popcount 为 $(01 + 16 + 215)/22/6*8 == 2.18$,剩下41个重复15次配平。
Flag2 类似，但开头要对齐比特边界，后面就是正常的目标字节串 → 二进制 → 6bit 切片 → 符号序列补齐频率 保证 Huffman 树稳定→加上 shuffle+XOR 逆操作 生成payload

不经意的逆转

RSA题,由中国剩余定理$(p+q)^d\equiv p^d+q^d\pmod n$
取$v=x_1$
$$v_0\equiv (x_1-x_0)^d+(p+q)^d+f \pmod n$$
$$v_1\equiv 0^d+(p-q)^d+f \equiv (p-q)^d+f \pmod n$$
消去f，$v_0-v_1 \equiv (x_1-x_0)^d+2q^d \pmod n$,$(v_0-v_1)^e \equiv (x_1-x_0)^{de} \equiv x_1-x_0 \pmod q$,即$q=gcd(n,(v_0-v_1)^e-(x_1-x_0))
