NFC技术浅谈

发表于2026-06-27|更新于2026-06-28

NFC 是什么

NFC(Near-field communication),是RFID(Radio-frequency identification)的演进分支,RFID是LF(如ID card,Frequency: 125 kHz),HF,UHF等不同工作频段的射频识别技术总称.
而NFC属于高频RFID的一个子集,为工作频率13.56Mhz的近场通讯协议.

NFC 的底层协议

常见的NFC底层协议有3大类

  1. ISO/IEC 14443,对应NFC-A,NFC-B
  2. JIS 6319-4,对应NFC-F,即Felica
  3. ISO/IEC 15693,对应NFC-V
    当然在此基础上向下兼容ISO 14443 Type A和JIS X 6319-4的ISO/IEC 18092(NFCIP-1)也出现(不包含NFC-B),用于诸如手机模拟卡的用途,而新的ISO/IEC 21481 (NFCIP-2)同时包括了以上三大类的NFC底层协议.
    基于3大类有ThinFilm,Topaz,LTO-CM,LEGIC,TEXKOM,Fuji/Xerox,iCLASS/PicoPass等各个厂家的分支

ISO/IEC 14443

基础射频层(ISO 14443-3)

包括了NFC-A 与 NFC-B两种底层协议
NFC-A(ISO 14443-3 Type A):100%的ASK调制,基于曼彻斯特编码
当读卡器靠近一张 Type A 卡片时,NFC-A 负责唤醒卡片(REQA),并在一堆卡片中选中目标卡片(Anticollision).
NFC-B(ISO 14443-3 Type B):10%的ASK调制,基于NRZ编码
负责 Type B 体系下的唤醒(REQB)和防冲突(ATTRIB 命令).

传输协议层 IsoDep (ISO 14443-4)

ISO 14443 标准的第 4 部分(ISO 14443-4)定义了一套高级的数据交换协议(Data Exchange Protocol,简称 DEP),在底层的 NFC-A 或 NFC-B 建立好连接后,IsoDep 接管通信,IsoDep 协议最主要的作用就是作为通道,用来传输 APDU (Application Protocol Data Unit) 指令.

例子

我们拿市售的NXP的NTAG 213举例:
用PM3来detect

读卡器启动(Initiation):在开启射频场后,读卡器至少等待 5 毫秒,然后发送 REQA 命令(十六进制表示为 0x26),唤醒范围内所有 A 型卡/标签.
标签响应(ATQA):标签通过发送 ATQA (请求应答)来响应 REQA.这个 2 字节的响应为读取器提供关键信息,包括标签的 [UID 大小] 和防碰撞属性.
防冲突循环(Anticollision Loop):当读写器(PCD)在磁场中存在多张卡片(PICC)时,通过二叉树搜索逐位识别并锁定其中单张卡片 UID,利用副载波曼彻斯特编码(Manchester Coding),强制指定第一个发生冲突的比特位为0,要求符号条件的所有卡片继续往下报 UID,直到给出一张完整的 UID,由于卡片 UID 长度不同(4, 7, 10 字节),防冲突分为三个级联级别(Cascade Level),每一级只处理 4 字节 的 UID 部分.拿到 4 字节 UID 后读写器立刻发送 SELECT 命令来选择这张卡.
SELECT 与 SAK:发送 SELECT 帧:

(NVB 固定为 0x70,代表 7 个完整字节).
卡片返回 SAK (1 字节): 如果 SAK & 0x04 == 0x04(第三位为1): 说明这是张双长度/三长度卡(如 7 字节的 NTAG),当前拿到的 UID0 其实是级联标记 0x88.读写器必须步进到 Cascade Level 2 (0x95),重复运行上述防冲突循环.如果 SAK & 0x04 == 0x00: 说明 UID 彻底接收完毕,卡片正式进入 ACTIVE 状态,可以开始传输数据或调用三层协议.

但是如果用NFC Tools PRO读取,可用字节是137,是因为格式化为 NDEF 协议所需的头部固定开销是7字节.

根据标准 NDEF(NFC Data Exchange Format)封装协议,在 144 字节的空白区域里写任何东西,都必须加上结构标记(TLV 格式):

  1. NDEF 消息起始标记 (T / Type): 固定占用 1 字节(值通常为 0x03),告诉读卡器接下来是标准 NDEF 数据.
  2. 数据长度声明 (L / Length): 固定占用 1 字节,记录你写的数据到底有多少个字节.
  3. 记录头控制字 (Header): 固定占用 1 字节,声明这条数据的类型.
  4. 类型长度声明 (Type Length): 固定占用 1 字节,例如写 0x01 表示类型只占 1 字节.
  5. 实际数据长度 (Payload Length): 固定占用 1 字节,实际写入数据的长度.
  6. 数据类型声明 (Type): 标识数据类型(如 U 代表 URL,T 代表文本).
  7. 有效载荷 (Payload): 自定义空间
  8. 结束标记 (E / Terminator): 固定占用 1 字节(值通常为 0xFE),代表数据到此结束.

Lock Control TLV (动态锁控制):01 03 A0 0C (Page 4) + 34 (Page 5):

字节 (Hex) 字段 含义
01 TLV Tag 标识这是一个 Lock Control TLV(锁控制信息).
03 Length 表示该控制信息后面跟着 3 个字节 的数据.
A0 Value 1 锁区配置数据: 定义了动态锁字节在内存中的位置.
0C Value 2 锁区配置数据: 定义了锁定位覆盖的页数.
34 Value 3 锁区配置数据: 定义了每个锁定位控制的字节数.

在第五页:03 52 DA,03 TLV Tag,52对应82字节
NDEF Header:0xDA 转换为二进制是 1101 1010
Bit 7 (MB) = 1: Message Begin 这是消息的第一个记录.
Bit 6 (ME) = 1: Message End 这也是消息的最后一个记录. (说明这段 NDEF 只有一个 Record)
Bit 5 (CF) = 0: 没有分块传输.
Bit 4 (SR) = 1: Short Record(短记录).说明数据的 Payload Length 字段只占用 1 个字节(总长 82 字节,没超过 255).
Bit 3 (IL) = 1: ID Length Present.写入 NDEF 时,强行包含了一个自定义的 ID 字段.
Bit 2-0 (TNF) = 010 (0x02): MIME Media-type.这说明存入的不是普通的网址 (URI) 或纯文本 (Text),而是一个自定义的 MIME 类型文件或数据结构(比如 application/json 或某种特定 App 的交互协议).
page 6: 17 36 01 61
|字节 (Hex)|字段|十进制/ASCII|核心含义|
|17|Type Length|23|紧跟在后面的 MIME 类型名称长达 23 个字节.|
|36|Payload Length|54|传输的实际核心数据(有效载荷)长达 54 个字节.|
|01|ID Length|1|自定义 ID 的长度为 1 个字节.|
|61|Type 的第一个字符|’a’|0x61 是小写字母 ‘a’ 的 ASCII 码.|

NDEF Header: 1 字节 (DA)
Type Length: 1 字节 (17)
Payload Length: 1 字节 (36)
ID Length: 1 字节 (01)
Type 字符串: 23 字节
ID 字符串: 1 字节
Payload 数据: 54 字节
总和：1 + 1 + 1 + 1 + 23 + 1 + 54 = 82 字节
MIME 类型长度刚好是 23 个字节,并且以字母 ‘a’ 开头,是application/vnd.wfa.wsc代表该 NFC 标签被写入了 Wi-Fi 简单配置.

但Proxmark3的解析文本存在Bug

在 WSC 协议中，数据是按照 TLV (Type-Length-Value) 格式封装的。PM3 提取出来的 00 02 00 08 其实是 Length (长度) 和 Value (值) 的组合:
00 02：代表后面的值占用 2 个字节.
00 08：加密类型.
根据 Wi-Fi Simple Configuration 官方规范中的“加密类型(Encryption Type, 属性 ID 0x100F)”字典表，对应关系如下:
0x0001 = None (无加密)
0x0002 = WEP
0x0004 = TKIP
0x0008 = AES
0x000C = TKIP/AES 混合模式
应该是AES
同时认证类型：00 02 00 22
在 WPS 规范中，这也是可以通过位运算(Bitmask)组合的：
0x0002 = WPA-PSK (WPA 个人版)
0x0020 = WPA2-PSK (WPA2 个人版)
0x0002 + 0x0020 = 0x0022 配置为 WPA/WPA2 混合模式
